# 《九州·缥缈录》微信小游戏 MVP 设计稿

## 1. 项目目标

本项目要做的是一个基于《九州·缥缈录》世界观的微信小游戏 MVP，产品形态为：

- 单机
- 线性剧情
- 轻自走棋 / 自动战斗
- 可直接作为微信小游戏上线验证

本版不是要做完整商业游戏，而是做一个可玩的最小验证版本，用来确认以下问题：

1. 能否做出一个完整可运行、可上线的微信小游戏闭环
2. 《缥缈录》的剧情人物和九州世界观是否适合做轻策略玩法
3. “自动战斗 + 手动一次技能 + 简单站位”是否足够形成基本可玩性
4. 原著党是否会认可题材表达，新玩家是否能看懂并被吸引

优先级明确如下：

1. 先做出来并可上线
2. 再验证玩法是否成立
3. 再验证题材吸引力
4. 商业化放在后续版本考虑

## 2. 用户定位

目标用户分两层：

### 2.1 核心用户

- 看过《九州·缥缈录》
- 或熟悉九州世界观
- 对阿苏勒、姬野、羽然等角色有情感基础

这类用户是首版最重要的传播和反馈来源。他们会天然关注人物还原、剧情气质、阵营设定和世界观味道。

### 2.2 扩展用户

- 没看过原著
- 但愿意尝试剧情类或轻策略类微信小游戏

这类用户不应被原著门槛劝退，因此本版的剧情表达必须做到：

- 不依赖大量背景知识
- 用少量文本交代角色关系和局势
- 让玩家先理解人物，再逐步感知九州世界的宏大感

结论：本项目应采用“原著党优先、新玩家可进入”的设计原则。

## 3. 产品形态与范围

本版产品定义为：

- 微信小游戏
- 2D
- 单机本地存档
- 单章节 5 关线性推进
- 3 个可选主角
- 轻量战斗系统

本版明确不做：

- 联网对战
- 排行榜
- 商店刷新
- 金币经营
- 抽卡
- 关外养成
- 装备系统
- 背包系统
- 社交系统
- 复杂分支剧情

范围控制原则：

- 先验证闭环，不追求完整自走棋
- 先验证人物与剧情，不追求大量内容
- 先验证轻策略决策，不追求复杂数值体系

## 4. 玩法定位

本项目采用“剧情向轻自走棋”方案。

它不是标准竞技自走棋，也不是纯剧情点击游戏，而是位于中间位置：

- 有上阵和站位
- 有自动战斗
- 有角色差异
- 有少量羁绊
- 有一次关键手动技能决策

但不会引入标准自走棋的完整经济和随机商店系统。

这样设计的原因是：

- 保留你最初想要的“阵营/角色/羁绊”表达
- 显著降低首次开发难度
- 更适合承载《缥缈录》的主线剧情体验
- 更适合微信小游戏的轻量时长和资源约束

## 5. 核心循环

单局与单章节循环如下：

1. 进入主线章节
2. 播放关前剧情文本 / 对话
3. 进入布阵界面
4. 玩家调整当前可用角色站位
5. 开始自动战斗
6. 玩家在战斗中手动释放一次主角技能
7. 战斗结算
8. 播放关后剧情文本；在第二关和第三关结算后分别解锁下一位主角
9. 进入下一关

第一章 5 关打完后，形成完整章节闭环。

这个循环的目标是：

- 让战斗尽可能容易理解
- 让剧情推进始终保持存在感
- 让玩家保留一个关键操作点，而不是完全旁观

## 6. 章节结构

本版只做一个章节，主题为：

`三位主角相遇、建立关系并完成首次并肩作战`

这比直接做北都大战、殇阳关等大战场更适合 MVP，因为：

- 人物辨识度更高
- 新玩家更容易进入
- 美术和关卡规模更可控
- 原著党也能快速感知“味道对不对”

### 6.1 第一关：乱世来客

定位：教学关

功能目标：

- 完成主角三选一
- 学会基础站位
- 学会自动战斗观看
- 学会手动释放一次技能

剧情目标：

- 让玩家知道自己选的是谁
- 知道自己为什么会卷入局势

### 6.2 第二关：南淮初会

定位：双人组合初成

功能目标：

- 第二位核心角色加入
- 首次体验双人站位配合
- 引入最基础的标签加成概念

剧情目标：

- 推进主角之间的第一次正式连接

### 6.3 第三关：街巷风波

定位：第一道策略门槛

功能目标：

- 提升敌方压力
- 让玩家感知站位和技能时机的重要性

剧情目标：

- 从“相识”推进到“开始信任”

### 6.4 第四关：并肩破敌

定位：三人组正式成形

功能目标：

- 第三位主角入队
- 首次三人同场
- 引入唯一核心羁绊

剧情目标：

- 明确三位主角之间的情感连接

### 6.5 第五关：一生之盟

定位：章节收束关

功能目标：

- 战斗完整度高于前四关
- 采用两波敌人结构，第二波包含一个小型首领
- 让玩家明显感觉到章节高潮

剧情目标：

- 形成情绪收束
- 让玩家知道九州更大的舞台正在展开

## 7. 主角设计

MVP 首发只做 3 个主角：

- 阿苏勒
- 姬野
- 羽然

原因如下：

- 原著辨识度最高
- 能直接代表《缥缈录》的核心情感结构
- 角色关系比单纯阵营设定更能带动新玩家进入世界

### 7.1 使用方式

玩家在开局时三选一做主角。

被选中的角色：

- 作为开局视角角色
- 拥有本局可手动释放的主角技能
- 先进入战斗阵容

另外两位主角：

- 按主线推进逐步解锁
- 在后续关卡中加入阵容

这种方式的价值：

- 提供代入感
- 强化“从谁的视角进入九州”
- 为 MVP 提供最小重玩价值

### 7.2 阿苏勒

定位：后排辅助 / 控场

角色气质：

- 隐忍
- 敏感
- 承担感强

战斗表现：

- 普通攻击较弱
- 擅长为全队提供增益

技能：

`苍狼祝祷`

效果：

- 释放后 8 秒内全队伤害减免提升 20%
- 适合在敌方第二波或首领爆发阶段使用

### 7.3 姬野

定位：前排输出 / 突进

角色气质：

- 锋利
- 强硬
- 不服输

战斗表现：

- 基础输出最高
- 适合放在前排左/右侧翼

技能：

`虎牙破阵`

效果：

- 向前突进一格并对路径终点周围敌人造成高额范围伤害

### 7.4 羽然

定位：中后排灵巧 / 干扰

角色气质：

- 轻盈
- 自由
- 灵动

战斗表现：

- 攻速快
- 身板较脆
- 适合风筝和收尾

技能：

`风羽回旋`

效果：

- 对最近的最多 3 名敌人造成连续弹射伤害
- 命中的敌人减速 2 秒

## 8. 羁绊与标签系统

本版不做大规模种族树，只做最小可解释羁绊。

设计原则：

- 世界观可感知
- 规则尽量少
- 不让新玩家背设定

### 8.1 主角同行

触发条件：

- 阿苏勒、姬野、羽然同时在场

效果：

- 全队攻击提升 10%，闪避提升 5%

作用：

- 这是 MVP 最重要的情感羁绊
- 直接服务“三人组”成形剧情

### 8.2 北陆血脉

触发条件：

- 北陆标签角色达到指定数量

效果：

- 生命值提升 15%

作用：

- 体现草原部族厚重、耐战的风格

### 8.3 东陆游侠

触发条件：

- 东陆 / 轻敏捷标签角色达到指定数量

效果：

- 攻击速度提升 12%

作用：

- 体现与北陆完全不同的战斗风格

说明：

MVP 阶段的“种族/阵营”本质上是标签系统，不是完整世界模拟。  
目的是让玩家感知九州人物来自不同文明体系，而不是完整搭建庞大规则树。

## 9. 战斗系统

### 9.1 基础规则

- 战斗自动进行
- 玩家战前调整站位
- 每关只允许手动释放一次主角技能
- 若关卡中出现多波敌人，技能时机成为主要决策点

### 9.2 站位设计

采用 `3x2` 格子布局。

选择原因：

- 足够容纳 1 到 3 名主角和少量友军
- 手机屏幕点击区域清晰
- 布阵复杂度最低

### 9.3 决策重点

玩家在战斗中的核心决策只有两个：

- 站位怎么摆
- 技能何时放

这两个决策足以支撑 MVP，不应再往里叠加太多系统。

### 9.4 敌人设计

MVP 敌方单位建议控制在以下 5 类以内：

- 近战杂兵
- 远程杂兵
- 盾兵
- 精英敌人
- 关底首领

这样既能形成战斗差异，又不会把制作成本拉高。

## 10. UI 结构

只做以下页面：

- 启动页
- 主菜单
- 主角选择页
- 章节 / 关卡页
- 布阵页
- 战斗页
- 结算页

### 10.1 主菜单

包含：

- 开始游戏
- 继续游戏
- 极简角色介绍

### 10.2 主角选择页

每位主角展示：

- 立绘头像
- 一句话性格介绍
- 一句话技能说明

### 10.3 章节页

- 展示 5 关线性进度
- 不允许跳关

### 10.4 布阵页

- 拖拽或点击换位
- 展示角色血量、定位、技能提示

### 10.5 战斗页

- 自动战斗画面
- 主角技能按钮
- 血量条
- 波次
- 暂停按钮

### 10.6 结算页

- 胜利 / 失败
- 下一关入口
- 新角色解锁或剧情推进提示

## 11. 美术与音频方向

MVP 美术方向定为：

- 偏简化卡牌 / UI 风
- 角色使用静态立绘头像
- 战斗使用小单位或简化小人

不追求：

- 完整大立绘演出
- 复杂动作骨骼
- 大量技能特效

选择这一方向的原因：

- 明显降低成本
- 更适合微信小游戏包体
- 更利于首次开发快速出结果

音频建议最小集合：

- 1 首主界面音乐
- 1 首战斗音乐
- 1 首结算音乐
- 基础点击、技能、受击、胜败音效

## 12. 技术建议

### 12.1 平台

- 微信小游戏

### 12.2 技术路线

推荐引擎：

- `Cocos Creator`

推荐原因：

- 对微信小游戏适配成熟
- 2D UI 和场景搭建效率高
- 中文资料和社区相对丰富
- 比纯原生小游戏 API 更适合首次开发

### 12.3 数据与存档

本地存档优先，内容包括：

- 当前章节进度
- 已选主角
- 已解锁角色
- 当前通关状态

首版不需要服务端。

### 12.4 性能与资源原则

- 角色资源尽量复用
- 特效数量严格控制
- 文本演出简单直接
- 保持首包轻量

## 13. 成功标准

本版 MVP 成功，不以收入或大量留存为目标，而以以下标准衡量：

### 13.1 产品完成度

- 能完整跑通：选主角 -> 过 5 关 -> 看到章节结尾

### 13.2 玩法可理解性

- 玩家能理解站位为什么重要
- 玩家能理解手动技能释放时机为什么重要

### 13.3 角色辨识度

- 玩家能说出阿苏勒、姬野、羽然三人的差异

### 13.4 题材感知

- 原著党觉得角色和氛围基本“有九州味”
- 新玩家能感受到这是一个更大世界的开始

## 14. 失败信号

以下情况意味着设计需要回炉：

- 玩家觉得战斗只是“看数值自动打”，没有决策感
- 三位主角技能区分度不明显
- 剧情过碎，看不懂人物关系
- 关卡推进没有情绪起伏
- UI 过于复杂或信息噪声太大

## 15. 后续版本方向

如果 MVP 验证成立，可在后续版本逐步增加：

- 更多章节
- 更多角色
- 更完整的阵营 / 羁绊
- 轻养成系统
- 轻商店或轻随机强化
- 图鉴和世界观收集
- 更丰富的剧情演出

但这些内容都不应进入当前 MVP 范围。

## 16. 最终结论

《九州·缥缈录》非常适合做“剧情向轻自走棋”微信小游戏，但前提是严格控制范围。  
本版最合理的 MVP 形态是：

- 单机
- 线性 5 关
- 3 位主角
- 自动战斗
- 一次手动技能
- 极简羁绊
- 极简 UI
- 极简内容资产

这能最大化保证你第一次做游戏时“做得完、能上线、能验证”，同时保留足够的九州辨识度。
